# sort-out — 项目文档整理与维护

两类工作，同一套流程：

1. **对齐**：根据项目状态更新文档——状态快照、验证基线、索引、过期内容，按 config 的「更新时机」逐份刷新。
2. **整理**：结构收敛——归档历史、消除重复、澄清权威、修复引用、补齐缺失。

目标：「哪份文档说什么、以谁为准、什么时候更新」永远清楚。

## 五条原则

1. **状态对齐直接做，结构改动先批准**。按 config 更新时机刷新内容、修死链、同步索引是本职工作，直接做并在报告中列出；新建/合并/移动/删除文档必须先出方案、等用户批准——那是别人写的内容，删除不可逆。
2. **红线高于整洁**。入库 vs 本地的边界绝不因「放这里更好找」而打破。发现越界内容，报告并给出处置建议，不自行决定。
3. **单源 + 指针**。一个事实只在一处维护；其他位置放指针（链接 + 一句话），不复制正文。
4. **现状文档不记历史**。状态类文档（如 AGENTS.md）只记「现在是什么、怎么做、约束是什么、用户偏好」，不记「过去发生过什么」——版本内容、已提交记录、里程碑一律移出。历史先查 git tag / issue 能否回溯：能，直接删；不能（如 gitignore 的本地文件），备份后再删。历史层积是现状文档混乱的首要来源。
5. **依赖包文档不动**。`node_modules/`、`site-packages/`等第三方依赖目录里的文档只读不写，不纳入整理范围。
## 标准文档集（必备 + 推荐）

每个项目**至少**要有三份；初次执行对照盘点，缺的问用户要不要建：

| 必备 | 作用 |
|---|---|
| `AGENTS.md` | Agent 工作说明：关键信息、硬约束、用户偏好/约定；**不记项目历史** |
| 架构文档 | 架构基线：拓扑、模块职责、数据流、设计契约 |
| 测试文档 | 测试体系：怎么跑、怎么写、mock/E2E/CI 约定 |

推荐补充（生命周期长、值得单独成档）：

| 文档 | 作用 |
|---|---|
| 文档索引（如 `docs/README.md`） | 每份文档干什么、以谁为准（面向人；与 config 同步） |
| ADR（`docs/adr/`） | 不可逆的架构/约束决策，一事一条，只增不改（废弃标注 superseded） |
| 运行/发版手册 | 操作知识：部署、发版、环境、故障处理 |
| 经验/踩坑文档（如 `LESSONS.md`） | 长期有效的教训：现象 / 原因 / 解法 / 适用条件；**不记事件流水**。手册引用它，不重复展开 |
| 术语表（glossary / `CONTEXT.md`） | 领域语言对齐，减少歧义 |
| README | 面向使用者的入口（产品介绍、快速开始） |

判断标准：**稳定**（写一次长期有效）且**重要**（错了会误导决策）才单独成档。易变的「状态/进度/做了什么」放 AGENTS.md 状态快照或 issue，**别建文档养它**。经验/踩坑文档收的也是稳定物：一条坑 = 现象/原因/解法，能指导下次行动；只叙述「何时谁踩了坑」的事件流水不收。

## 配置：`sort-out.config.txt`

项目根目录一份，是本 skill 的运行配置：每份文档的**作用、位置（入库/本地）、权威范围、更新时机、角色（必备/推荐/自定义）**。

**初次执行**（config 不存在）——必须采访，不得凭猜测代填：

1. 盘点现有文档 + 对照标准文档集列缺口；
2. **向用户提问并等回答**：每份文档的作用、权威、更新时机；缺口/推荐项建不建；
3. 答案写成 `sort-out.config.txt`；`docs/README.md` 同步登记。

**每次执行**：读 config → 按「更新时机」把文档对齐到项目当前状态 → 走整理流程。文档增删或作用变化时同步更新 config 与 `docs/README.md`。

格式（纯文本，一节一文档；「更新时机」取值：`每次运行` / `相关变更时` / `手动`）：

```
# sort-out.config.txt — 文档作用与更新策略（本地，不入库）
# 初次执行由 /sort-out 采访生成；文档增删/作用变化时同步更新。
# 本文件面向 /sort-out 运行，docs/README.md 面向人，两者保持一致。

[AGENTS.md]
角色: 必备
位置: 本地
作用: Agent 工作说明：关键信息/硬约束/用户偏好/操作手册；不记项目历史
权威: 当前状态、验证基线、硬约束
更新时机: 每次运行

[架构文档]
角色: 必备
位置: 本地
作用: 架构基线（拓扑/模块职责/数据流/设计契约）
权威: 架构与模块职责
更新时机: 相关变更时
```

## 工作流

### 第 0 步：配置检查

读 `sort-out.config.txt`。不存在 → 走「初次执行」流程（采访用户后创建），**采访前不动任何文档**。

### 第 1 步：盘点（只读）

现场枚举，不凭记忆——文档状态每次都不同，硬编码的清单本身就会陈旧：

```bash
find docs -type f | sort
wc -l *.md *.txt 2>/dev/null
git ls-files '*.md' | grep -vE '^(node_modules|\.venv|site-packages|vendor|dist|build)/' | sort
git status --short                              # 跟踪状态（未登记/未提交的文档会现形）
```

对照 config（含标准文档集）输出盘点表：**路径 / 行数 / 角色 / 更新时机 / 问题初判**，并列两类异常：**缺口**（必备文档缺失）、**孤儿**（盘里有但 config 未登记）。

### 第 2 步：诊断（只读）

逐份通读，按六类问题记录证据（`文件:行号`）：

1. **状态过期**：内容与项目当前状态不符（旧数字、已关闭的「进行中」、过期语义）→ 对齐。
2. **时间层积**：现状文件里堆着带日期的历史叙述（「XX 进行中」「最近已提交」「更早：……」）→ 历史移出（原则 4）。
3. **重复**：同一事实多处维护 → 单源化。
4. **权威冲突**：两份文档对同一主题都自称权威 → 按 config 的「权威」字段裁决，不新造权威。
5. **越界**：敏感/内部内容位于可跟踪文件，或入库内容被整段复制进本地文件 → 红线，单独列出交用户决定。
6. **死链**：交叉引用指向不存在的文件、章节或条目。

### 第 3 步：方案

- **状态对齐类**（按更新时机刷新内容、修死链、同步索引）：直接做，报告中列出。
- **结构改动类**（新建/合并/移动/删除文档、改角色）：每条一行 `文件 → 动作 → 理由`，含 **Must / Must Not / Unresolved** 三栏——未决项明确列出，不擅自补全；标注动的是入库还是本地文件；**停下等批准**。
- 删除清单：删除前先备份到 `/tmp/opencode/docs-backup-$(date +%Y%m%d)/`（git 历史可回溯的除外）。

### 第 4 步：执行

- surgical 地改，不顺手「改进」无关内容；
- 历史移出现状文档（归档或删——git 可回溯的不心疼，本地文件删前必须已备份）；
- 单源化：保留权威处，其余改成一指针；
- 任何文档增删移动后，同步更新 `sort-out.config.txt` 与 `docs/README.md`（索引只做索引，不复制内容）。
- 跳过所有第三方依赖目录（node_modules/、.venv/、site-packages/、vendor/ 等），不读取、不修改其中的文档。
### 第 5 步：验证

- 所有交叉引用可解析（grep 出 `](./`、「见 ……」类引用逐个核对）；
- `git status` 无意外：gitignored 的本地文件绝不出现在待提交区；
- 复查整理后的入库文件不含内部端点、密钥、交接内容；
- 报告 before/after：文件数、总行数、本次对齐了什么、消除了什么问题。

## 本项目补充红线

- **文档一律入库**（2026-10-02 起，私有仓库）：`AGENTS.md`、`CONTEXT.md`、`omini-shift-arch.md`、`LESSONS.md`、`sort-out.config.txt` 均随仓库 git add。唯一红线：**密钥/凭据值绝不入库**（`.env` 等，历史上有过误入库事故，git 历史无法撤回）；文档只写密钥的引用名与获取方式。
- **`AGENTS.md` 的角色**：关键信息 + 硬约束 + 用户偏好/约定 + 操作手册（发版、环境、工具），**不记项目历史**（版本内容、已提交记录、里程碑）。

## 常见坑

- **别把整理做成重写**：目标是结构收敛与状态对齐。遇到「顺手把这段也改准确点」的冲动，记入 Unresolved 让用户决定。
- **别在本 skill 里维护文档清单**：文档会漂移，每次现场盘点（第 1 步）。
- **别跳过初次采访**：config 的角色/权威/更新时机是用户决策，猜错会把文档更新到错误的方向。
- **别把状态写进稳定文档**：进度、做了什么、版本内容属于状态快照或 issue；写进架构/测试文档就是下一次时间层积。
