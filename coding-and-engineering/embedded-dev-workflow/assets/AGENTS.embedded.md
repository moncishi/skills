## 开发规则
- 编译、打包与刷机命令（经源码核对）：见 `docs/build_and_flash.md`
- 使用任何命令前，先在现有代码/脚本中 grep 它的真实用法，并说明出处
- 开发阶段看门狗已禁用（方法：____），不要恢复
- 新器件先加 debug 输出（ID / link / speed / 状态寄存器），再调功能
- 一次只改一个变量
- 复位必须显式：拉低 → 等待 ____ ms → 释放 → 等待 ____ ms

## 排查规则
- 连续两次尝试失败后，列出至少 3 个候选假设（假设 / 支持证据 / 反对证据 / 验证方法），排序后再动手
- 回答中区分「已验证」与「推测」

## 验证规则（每次都要做）
1. 启动日志 `Model:` 字符串正确
2. `fdtdump` 编译产物中的目标节点正确
3. 二进制中确认改动存在（`objdump` / `strings`）
4. 烧录前后大小 + `crc32` 一致

- 每次尝试新建分支：`test/<基线>-<功能>-<序号>`
